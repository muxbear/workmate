# 技能下载站点扩充与按需抓取说明

> 前置说明见《技能下载站点参数化与下拉框修复说明.md》：下拉数据来自「参数配置」中的
> `skill_download_site` 参数，以及下拉面板被弹窗裁剪的修复。

## 1. 背景与结论

「技能 → +创建技能 → 从仓库下载」的来源下拉此前只有 2 个内置站点。本次联网调研当前流行的
Agent Skills 站点/仓库（GitHub Search API 按 star 排序 + Tavily 联网检索行业盘点），
按需求「**最权威、业界使用最多的前 5 个**」收敛后，在「参数配置 → `skill_download_site`」中
配置了 5 个子参数；其余调研结果见第 5 节附录（未启用，可按需补回）。

## 3. 后端配套改动（`web/backend/src/api/skill/repository.py`）

站点结构比原来的内置两个仓库更复杂，本次做了三处必要调整：

1. **技能目录支持多级嵌套与仓库根目录**：`_scan_tarball` 会在「技能目录」下按任意层级查找
   `SKILL.md`（如 `skills/engineering/<name>`、`skills/.curated/<name>`），并跳过已识别技能目录
   内部的嵌套 `SKILL.md`；参数值形如 `…/tree/main/.` 时表示技能就在仓库根目录。
   解压与入库使用技能目录名（basename），因此 `skills/engineering/ask-matt` 落盘为 `ask-matt`。
2. **按来源懒加载**：点「获取」只抓取当前选中的站点（原实现会一次性抓取全部来源，站点变多后
   请求数与下载量都不可控）。快照按来源做 TTL 缓存，榜单排名改为来源内「星标数 → 技能名」排序。
3. **快照上限保持 64MB**：当前 5 个站点最大约 32MB（ECC），如需抓取上百 MB 的大型合集仓库，
   可通过环境变量 `SKILL_REPO_MAX_TARBALL_MB` 调大。

## 6. 注意事项

1. GitHub 未鉴权额度为 60 次/小时，每个站点抓取消耗 2 次（仓库元信息 + tarball）；建议配置
   `SKILL_REPO_GITHUB_TOKEN` 提升配额。
2. `.gemini/skills` 这类软链接目录不会出现在 GitHub tarball 中，配置时必须使用真实目录
   （如仓库根目录 `.`）。
3. 市场类目录（skills.sh、ClawHub 等）需要各自实现 API 适配器后才能作为下载来源。
