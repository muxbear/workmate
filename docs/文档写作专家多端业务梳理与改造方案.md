# 文档写作专家多端业务梳理与改造方案

> 版本：v1.0　编制日期：2026-09-22
> 适用范围：桌面版（ke-work）、Web 版（ke-hermes）、后续移动版
> 关联模块：专家体系、输入卡「+」菜单、Agent 运行时、沙箱、会话产物（artifact）、文件预览、打包下载

---

## 0. 结论摘要

当前「文档写作专家」在两端都不是一个"能力包"，而是**一段平台耦合的提示词 + 一套靠猜测的产物识别逻辑**：

- 桌面版：文章、同名图片目录、消息内图片显示、工作区文件树均可正常工作（local 模式），**缺打包下载**，云端模式失效。
- Web 版：文章 Markdown 能被登记与预览，但**配图既不会被登记为产物，也不会在预览中正确显示**，二进制回灌还会写坏文件，属于"功能不可用"。
- 两端共用同一份写在数据库里的系统提示词，其中包含 `curl.exe` / PowerShell / `mkdir` / 反斜杠路径 / `cd` 等 Windows 专属命令，**移动端接入会原样继承全部缺陷**。

本次改造的核心：把「专家」抽象为**平台无关的能力包**（声明 + 提示词模板 + 交付物契约），把"落盘、下载、登记、预览、打包"下沉为各端实现的**运行时适配层**；Web 端配图改为**后端代理下载**，交付目录改为**会话 + 轮次子目录**，并补齐两端的**打包下载**。

已确认决策（与需求方逐条确认）：

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| D1 | 配图由**后端代理下载** | 沙箱不出网、不执行下载命令；后端下载后直接写入交付目录并持久化 |
| D2 | 打包下载按 **bundle（一轮回答）+ 整会话** 两种粒度 | 主入口是"本轮交付物"，另提供"打包整个会话" |
| D3 | 沙箱隔离**只改交付目录为会话子目录** | 不引入"每会话独立沙箱"，改动小、见效快 |

## 1. 背景与目标

### 1.1 现状（需求方描述）

- 桌面版「新建任务」页面输入框左下角「+」可添加「文档写作专家」；文章写完后在工作区生成文章与文章目录，配图保存在文章目录中。
- Web 版「对话」页面输入框左下角「+」同样可添加该专家；文章与配图保存在沙箱中，已有"物化存储 + 预览时回灌沙箱"的机制，但存在若干问题。

### 1.2 需求

1. 「文档写作专家」既可添加到桌面版「新建任务」输入框，也可添加到 Web 版对话输入框；
2. 两端按用户要求生成文章，并**正确显示文章配图**；
3. 生成的文章与配图**可打包下载**；
4. 专家**不得与桌面版 / Web 版耦合**，必须具备独立性，可适配两端，并能在后续适配移动端。

### 1.3 目标

- 功能正确性：两端"选专家 → 写文章 → 图能看 → 能打包拿走"全链路可用；
- 架构独立性：专家定义零平台痕迹，平台差异由适配层与提示词渲染层吸收；
- 可复用性：移动端只需实现适配层接口，专家与提示词无需改动。

## 2. 现状业务链路梳理

### 2.1 专家定义的唯一来源

内置专家在后端种子数据中创建：

- 名称 / 描述 / 分类 / MCP 关联：`web/backend/src/api/experts/service.py:844`（`BUILTIN_EXPERTS`）
- 系统提示词：`web/backend/src/api/experts/service.py:859` 起
- 种子写入与"已存在则更新"分支：`seed_builtin_experts()`（同文件末尾）

专家分发给两端：

| 端 | 通路 | 代码位置 |
| --- | --- | --- |
| Web | 直接读 DB，专家作为 subagent 注册 | `web/backend/src/agent/subagents/subagents_operate.py:40` |
| 桌面 | OAuth2 `expert:read` + `/api/expert-sync/list` 同步落盘 | `desktop/src/main/experts/ExpertSyncService.ts:86`、`web/backend/src/api/experts/sync_api.py` |

**关键点：两端消费的是同一条 `experts.system_prompt` 记录，因此提示词里任何平台专属写法都会同时污染两端（以及未来的移动端）。**

### 2.2 桌面版链路

1. 「+」菜单选专家 → `catalog.setExpert()`（`desktop/src/renderer/src/store/catalog.ts:245`）把提示词模板插入输入框，并记录 `selectedExpertId`。
2. 发送时 `window.api.setExperts([expert])`（`desktop/src/renderer/src/views/NewTaskPage.vue:468`）→ 主进程重建 agent（`desktop/src/main/agent/AgentManager.ts:209`），专家成为 subagent（`AgentManager.ts:45`）。
3. 后端：local 模式 `LocalShellBackend`（`desktop/src/main/agent/AgentBuilder.ts:79`，`rootDir` = 会话工作区），专家用文件工具 + `execute` 把文章与配图写入真实目录。
4. 产物识别：写工具入参 / 回复文本正则（`desktop/src/main/agent/doc-artifacts.ts:4`、`doc-artifacts.ts:66`），推给渲染层并在右侧栏打开。
5. 图片显示：
   - 外链图片 → 主进程下载缓存 + `ke-img://` 私有协议（`desktop/src/main/images/RemoteImageService.ts:96`）；
   - 工作区相对路径 → 读字节转 blob（`desktop/src/renderer/src/components/MessageContent.vue:358`）。
6. 工作区文件树展示文章与同名目录（`desktop/src/renderer/src/components/FileList.vue`）。

### 2.3 Web 版链路

1. 「+」菜单选专家 → `chatStore.setExpert()`（`web/frontend/src/components/chat/ChatPlusMenu.vue:172`），随请求发 `expert_id/expert_name`。
2. `/api/chat/stream` 把专家转成一句委派提示（`web/backend/src/api/agent/agent_api.py:258`），并注入工作区/权限提示（`agent_api.py:233`）。
3. 沙箱执行：`SandboxManager` 按 `user_id` 复用沙箱（`web/backend/src/agent/sandbox/sandbox_manager.py:71`），文件工具 / `execute` 在沙箱内运行。
4. 产物登记：从工具名关键词 + 参数名 + shell 重定向正则推断路径（`web/backend/src/api/agent/artifacts.py:39`、`artifacts.py:138`）。
5. 物化：登记后立刻从沙箱下载并写入持久存储（`artifacts.py:297`），存储根默认 `{WORKSPACE}/artifacts`（`web/backend/src/core/storage/artifact_store.py`）。
6. 回灌：沙箱重建后把就绪产物写回沙箱（`web/backend/src/agent/middleware/artifact_restore.py:97`）。
7. 预览 / 下载：`GET /api/chat/artifacts/{thread}/download`（`web/backend/src/api/agent/agent_api.py:826`）→ 右侧文档标签页 → `DocumentViewer.vue` → `MarkdownViewer.vue`。

### 2.4 两端差异对照

| 维度 | 桌面版 | Web 版 |
| --- | --- | --- |
| 专家触发 | 输入框插入提示词 + subagent | 仅服务端委派提示 |
| 专家工具来源 | `expert_tools` + MCP（`McpToolRegistry.ts`） | `expert_tools` + MCP（`registry.py`） |
| 文件落盘位置 | 本地工作区真实目录 | 沙箱虚拟文件系统 |
| 产物识别 | 写工具 + 回复文本正则，识别"文档产物" | 工具名关键词 + 重定向正则，识别"任意产物" |
| 二进制产物 | 天然是本地文件 | 依赖登记与物化 |
| 图片显示 | 外链走 `ke-img://`，相对路径读工作区字节 | **无任何解析** |
| 轮次归属 | 按轮持久化（`saveTurnArtifacts`，`main/index.ts:752`） | 全部挂到最后一条 AI 消息（`stores/chat.ts:715`） |
| 打包下载 | 无 | 无 |

## 3. 问题清单

### P0（功能正确性，必须修）

| 编号 | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| P0-1 | Web 端配图不会被登记为产物 | 提示词要求 `curl.exe -o` 下载图片，而识别器只认写文件工具与重定向 `>`/`>>`/`tee`（`artifacts.py:39`、`artifacts.py:58`）；`_normalize_path` 又要求路径以 `/` 开头（`artifacts.py:178`） | 配图不入库、不物化、不打包、沙箱过期即永久丢失 |
| P0-2 | Web 端 Markdown 预览不解析图片相对路径 | `MarkdownViewer.vue:9` 直接 `marked.parse`；`DocumentViewer.vue` 不传 threadId / basePath；`MessageItem.vue:71` 同样问题 | 文章内 `![](文章/figure-1.png)` 解析为站点相对地址 → 404 裂图（消息气泡与右侧预览都裂） |
| P0-3 | 沙箱回灌会写坏二进制 | `opensandbox_backend.py:223` `upload_files` 对 bytes 做 `decode("utf-8")`，失败回落 `str(content)`（`opensandbox_backend.py:257`） | 图片回灌进沙箱后成为文本乱码，"回灌后仍可访问"对二进制不成立 |
| P0-4 | 专家提示词与平台强耦合 | 提示词含 `curl.exe`、`powershell -NoProfile`、`if not exist ... mkdir`、反斜杠路径、`cd` 取物理路径（`service.py:859` 起） | Web 沙箱是 Linux，命令全部不可用；桌面云端模式无 `execute`；移动端会继承同样缺陷 |

### P1（体验与一致性）

| 编号 | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| P1-1 | 专家是"软委派"，不保证被使用 | `agent_api.py:258` 仅生成一句"请优先委派" | 用户以为已用专家，实际由主模型自行决定；两端行为不一致（桌面还额外插提示词） |
| P1-2 | 沙箱按用户复用，跨会话串文件 | `sandbox_manager.py:71` 只按 `user_id` 建沙箱；产物按 `(thread_id, path)` 记账 | 两个会话写同名 `文章.md` 时后写覆盖先写，A 会话可能物化到 B 的内容；且 `workspace_id` 提示（`workspace.py:39`）与专家"写工作区根 `/`"口径冲突 |

| --- | --- | --- | --- |

| P2-2 | 桌面"文档产物"白名单不含图片 | `desktop/src/main/agent/doc-artifacts.ts:4` | 图片永远不是消息产物，只能靠文件树发现 |

## 4. 目标设计

### 4.1 设计原则

> **专家只声明"做什么、交付什么"；平台负责"怎么落盘、怎么显示、怎么打包"。**

三条硬约束：

1. 专家定义（DB）中**不得出现**路径分隔符、shell 命令、平台目录约定；
2. 平台差异只能出现在**提示词渲染层**与**运行时适配层**；
3. 交付物必须是**显式登记 + 可枚举**的，不依赖对工具调用文本的猜测。

### 4.2 分层契约

```
① 专家定义层（平台无关，存 experts 表）
   capabilities      : ["image.generate", "document.assemble"]
   prompt_template    : 只描述写作意图与交付物契约，含变量占位
   deliverable_spec   : { root: "<title>.md",
                          resource_dir: "<title>/",
                          resource_pattern: "figure-{n}.{ext}" }
                 │ 服务端按 platform 渲染
                 ▼
② 运行时适配层（每端一份实现）
   WorkspacePort     : root() / list() / readBytes() / write()
   DeliverablePort   : downloadAsset(url, relPath) / register()
   PromptRenderer    : 注入 delivery_dir / 平台能力说明
                 │
                 ▼
③ 产物层（平台无关）
   Bundle = { thread_id, turn, root, resources[], manifest }
   预览 / 回灌 / 打包 / 展示 统一以 Bundle 为单位
```

### 4.3 交付目录与 Bundle 模型（对应决策 D3）

**Web 端（改）**：交付目录由"沙箱根 `/`"改为**会话 + 轮次子目录**

```
/artifacts/<thread_id>/turn-<n>/文章标题.md
/artifacts/<thread_id>/turn-<n>/文章标题/figure-1.png
/artifacts/<thread_id>/turn-<n>/文章标题/figure-2.png
```

- `/artifacts/` 是 `CompositeBackend` 的宿主路由，落到 `{WORKSPACE}/artifacts_agent/{user_id}/...`（`web/backend/src/agent/backends/user_scoped_filesystem_backend.py:23`），因此**天然按用户隔离、天然不依赖沙箱生命周期**；
- 追加 `thread_id` 解决跨会话同名覆盖（P1-2），追加 `turn-<n>` 天然形成 bundle（P1-3）；
- `n` 由服务端在每轮请求开始时计算：`该会话交付根下已有 turn-* 目录数 + 1`（免改表，可读、可排序）；若后续需要强一致，再引入 `chat_artifacts.turn_id` 列。

**桌面端（不变）**：仍写入工作区根目录（避免破坏用户既有习惯）。

> 注意：桌面端保留根目录写入意味着"同名文章跨会话覆盖"风险仍在，由现有提示词的"重名追加 -1/-2"约定兜底。若后续要求两端目录结构完全一致，可将桌面交付根改为 `<workspace>/<conversationId>/`，属于独立开关，不影响本方案其余部分。

### 4.4 配图获取：后端代理下载（对应决策 D1）

新增专家可用工具 `download_asset(url, rel_path)`，由**后端进程**完成，沙箱不参与：

```
1. 校验：仅 http(s)、超时、大小上限、content-type / 魔数双重校验、重定向次数限制
2. 目标：<会话交付目录>/<rel_path>（例：turn-2/文章标题/figure-1.png）
3. 落盘：写入宿主 staging（core.storage.agent_staging）
4. 登记 + 持久化：写 chat_artifacts 并直接保存到 ArtifactStore
   （status=ready、storage_key、mime_type、size、checksum，source_tool=download_asset）
5. 返回：{ path, size, mime_type, artifact_id }
```

收益：

- 沙箱**完全不需要出网**，彻底规避 P1-4；
- 图片"生成即持久化"，不再受沙箱 TTL、回灌、正则漏检影响（修 P0-1）；
- 图片 URL 签名过期不再影响预览（预览读持久副本）；
- 提示词不再需要任何下载命令，平台差异归零（配合 4.9 修 P0-4）。

桌面端实现同一语义工具：主进程下载并写入工作区同名目录（复用 `RemoteImageService` 已具备的下载 / 校验 / 魔数嗅探能力）。

### 4.5 产物登记：显式登记 + 目录扫描兜底

1. **显式登记**：`download_asset` 直接登记；文件工具写入交付目录后由轮末扫描登记。
2. **轮末扫描**（兜底，覆盖脚本产物）：交付目录在宿主，无需访问沙箱，直接遍历
   `{WORKSPACE}/artifacts_agent/{user}/{thread}/turn-<n>/`，与已登记集合求差集后补登记 + 物化。
3. 现有"工具名关键词 + 重定向正则"保留为第三层兜底，但必须扩展 `-o|--output|wget|python` 等模式，并放宽 `_normalize_path`：**相对路径按会话交付目录归一化，而不是直接丢弃**。

### 4.6 预览：相对路径 → 产物地址解析协议

统一规则（消息气泡与右侧预览共用同一个工具函数）：

```
输入：markdown 文本、threadId、basePath（当前 md 的虚拟路径）、会话产物清单
规则：
  1. ![alt](http(s)|data|blob)  → 原样
  2. ![alt](相对路径)           → resolve(basePath 所在目录, 相对路径)
  3. 命中产物清单               → artifactDownloadUrl(threadId, path, 'inline')
  4. 未命中                     → 保持原值（裂图但不影响整篇渲染）
```

落地要点：

- 新增共享工具 `web/frontend/src/utils/markdownArtifacts.ts`；
- `MarkdownViewer.vue`（右侧预览）与 `MessageItem.vue`（消息气泡）都必须接入——当前两处都是裸 `marked.parse`；
- `DocumentViewer.vue` / `types/document.ts` 需透传 `threadId`、`basePath`、`artifacts`；
- 兼容历史数据：`basePath` 为空时按会话交付根解析，命中不了就保持原值。

### 4.7 打包下载（对应决策 D2）

**Web 后端**：新增

```
GET /api/chat/artifacts/{thread_id}/bundle.zip?scope=turn|thread[&turn=turn-<n>]
```

- `scope=turn`：打包某一轮交付目录（默认取最新一轮）；
- `scope=thread`：打包整个会话交付目录（含全部轮次）；
- 保持原始目录结构，中文文件名按 UTF-8 写入 zip 条目；
- 无内容返回 404，越权（非本人会话）返回 404，不做空包。

**Web 前端**：产物卡片与文档标签页提供"打包下载本轮 / 打包整个会话"两个入口。

**桌面端**：新增 IPC `workspace:export-zip(workspaceId, relPaths[])`，主进程递归打包（可复用已依赖的 `fflate`），入口放在文件树与消息产物卡片。

### 4.8 回灌与二进制字节通道（修 P0-3）

- `upload_files` 改为**字节直通**（或对二进制走专用写接口），禁止 UTF-8 解码失败后回落 `str(content)`；
- 交付目录（`/artifacts/`）**不参与回灌**（现状已如此，`artifact_restore.py:116`），配合 4.3 后，文章与配图的日常读写都发生在宿主路由，回灌仅用于非交付类工作文件；
- 回灌上限（文件数 / 单文件大小）按会话产物集合整体判断，避免静默截断（对应 P2-3）。

### 4.9 平台化提示词渲染（修 P0-4）

| 变量 | Web | 桌面 |
| --- | --- | --- |
| `{{delivery_dir}}` | `/artifacts/<thread>/turn-<n>/` | 工作区根目录（`execute` 当前目录） |
| `{{asset_tool}}` | `download_asset` | `download_asset` |
| `{{file_tool_root}}` | `/artifacts/` | `/`（=工作区） |
| `{{platform_notes}}` | 沙箱为 Linux、无 shell 下载 | 本地工作区、图片目录同名 |

- 渲染发生在**服务端**：`GET /api/expert-sync/list?platform=desktop|web|mobile` 返回已渲染结果，桌面端只需带平台参数（`ExpertSyncService.ts` 改一处）；Web 端在 `chat_stream` 组装专家提示时使用同一渲染函数。

### 4.10 移动端适配路径

1. 服务端新增 `platform=mobile` 渲染分支；
2. 移动端实现三个 Port：工作区（应用沙盒目录）、`download_asset`（走服务端代理或本地网络库）、产物登记（上报到同一 `chat_artifacts` 或本地库）；
3. 预览复用同一"相对路径 → 产物地址"规则；
4. 专家定义、提示词模板、交付物契约**零改动**。

## 5. 端到端时序（Web 一轮写作）

```
用户：输入卡「+」→ 专家 → 输入写作要求 → 发送
  │
  ├─ 前端：body 带 expert_id / expert_name
  ├─ 后端 _resolve_selection：注入【专家】与【交付目录 /artifacts/<thread>/turn-<n>/】提示
  ├─ 主 agent 委派「文档写作专家」subagent
  │    ├─ 调 MCP text_to_image / text_to_image_batch 生成配图 → 得到临时 URL
  │    ├─ 调 download_asset(url, "文章标题/figure-1.png")
  │    │     └─ 后端代理下载 → 写宿主 staging → 登记 chat_artifacts → 持久化
  │    │        └─ SSE 推送 artifact 事件（含 status=ready）
  │    └─ 调 write_file("/artifacts/<thread>/turn-<n>/文章标题.md")
  ├─ 轮末：扫描 turn 目录补登记遗漏文件 + 补全大小 + 推送 artifact_updated
  └─ 前端：产物卡片（本轮 bundle）/ 消息气泡内图片 / 右侧预览 均通过 artifactDownloadUrl 加载
       └─ 打包下载：bundle.zip（本轮）或 thread.zip（整会话）
```

## 6. 分期计划与验收标准

### 6.1 P0（功能正确性，一个迭代）

P0-1 后端代理下载工具；P0-2 交付目录会话 + 轮次子目录；P0-3 平台化提示词；P0-4 预览相对路径解析；P0-5 二进制字节通道；P0-6 打包下载；P0-7 轮末扫描兜底。

**验收**：

1. Web 端选专家写文章 → 消息气泡与右侧预览**都能看到配图**；
2. 沙箱被回收（调小 `SANDBOX_TTL_SECONDS` 或手动 kill）后刷新页面，文章与配图仍可预览、可下载；
3. 打包下载 zip 结构与交付目录一致：`文章标题.md` + `文章标题/figure-1.png`；
4. 同一会话连续两轮写作 → 生成 `turn-1/`、`turn-2/`，两轮 bundle 互不覆盖；
5. 不同会话写同名文章 → 目录隔离，内容不串；
6. 桌面端同一专家、同一提示词（无 Windows 专属命令依赖）产出文章 + 配图，并可打包下载；
7. 专家提示词中不再出现 `curl.exe` / `powershell` / `mkdir` 等平台命令（可用断言测试固化）。

### 6.2 P1（体验一致性）

- 产物卡片按轮分组（修 P1-3 的展示面）；
- 专家委派强化（命中写作意图时强制走 subagent，或直接将专家提示词并入本轮系统提示）；
- 桌面 `setExperts` 改为会话态；
- 打包入口文案与交互统一（本轮 / 整会话）。

### 6.3 P2（架构与多端）

- 抽 `expert-contract`（TS）+ `expert_contract`（Python）公共契约包；
- 专家 `capabilities` 声明式能力映射（替代工具名硬编码）；
- 移动端接入。

## 9. 风险、兼容与回滚

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 模型不调用 `download_asset` | 仍可能直接输出临时 URL | 提示词强约束；预览层对 `http(s)` 图片可做一次后端代理缓存（P1）；产物卡片保持可见 |
| 存量 staging 清理影响交付目录 | `purge_agent_staging` 按 `ARTIFACT_RETENTION_DAYS`（默认 30 天）清理宿主交付目录 | 已物化副本仍在 `ArtifactStore`，预览 / 下载不受影响；仅"沙箱内再读写"失效，需要时加"按需从持久层回填 staging"（P1） |
| 老文章路径不兼容 | 老数据在沙箱根 | 解析函数对 `basePath` 缺失 / 未命中保持原值，不报错 |
| 桌面目录结构不变带来的同名覆盖 | 桌面仍写工作区根 | 保留既有 `-1/-2` 约定；如需彻底一致可后续启用 `<workspace>/<conversationId>/` 开关 |
| 回滚 | P0 无表结构变更 | 关闭新工具与提示词渲染（配置开关）、保留旧提示词模板即可回退；`bundle.zip` 为新增只读端点，不影响既有接口 |

### 16.3 缺陷一：<img> 无法携带鉴权，配图 401

- 现象：消息气泡与右侧 Markdown 预览里所有配图裂图；同一地址匿名请求返回 401，带 `Authorization: Bearer` 返回 200（image/png）。
- 根因：`artifactDownloadUrl()` 生成的是裸地址，被直接当作 `<img src>` 使用，浏览器不会附带 Authorization 头。
- 修复：前端统一改为「带鉴权拉取字节 → 生成 blob 对象地址 → 渲染时替换」，不引入 URL 传参形式的 token。
  - 新增 `useArtifactImages` composable（同一会话同路径跨组件共享缓存 + 引用计数释放）；
  - `markdownArtifacts.ts` 拆出 `resolveArtifactImage()`（返回产物会话与虚拟路径，供鉴权拉取使用）；
  - `artifactApi.ts` 新增 `fetchArtifactObjectUrl()`；
  - `MessageItem.vue` / `MarkdownViewer.vue` 接入该 composable。
- 关键文件：`web/frontend/src/composables/useArtifactImages.ts`（新增）、`web/frontend/src/utils/markdownArtifacts.ts`、`web/frontend/src/services/artifactApi.ts`、`web/frontend/src/components/MessageItem.vue`、`web/frontend/src/components/chat/viewers/MarkdownViewer.vue`。

### 16.4 缺陷二：当轮不推送 `artifact` 事件，交付物卡片缺失

- 现象：一轮生成结束后，SSE 只有 `selection / agent_start / tool_start|end / token / agent_end / done`，没有任何 `artifact` 事件；消息里没有「本轮交付物」卡片与「打包下载」入口，刷新重开会话后才出现。
- 根因：`download_asset` 在工具内部直接登记产物（`ingest_remote_asset`），随后基于工具入参的登记逻辑 `record_artifacts()` 只会看到「已存在」、返回空，因此不会推送 `artifact` 事件；轮末的 `artifact_updated` 在渲染层只更新"已挂载到消息上的"产物，不会新挂。
- 修复：新增纯函数 `pick_turn_artifacts(items, delivery_dir, emitted)`，按「本轮交付目录前缀 + 已推送集合」求差集，作为事件推送的统一出口；在主流程两处调用：每次 `tool_end` 之后、以及轮末扫描与元信息补全之后。
  - 关键文件：`web/backend/src/api/agent/artifacts.py`、`web/backend/src/api/agent/agent_api.py`。
