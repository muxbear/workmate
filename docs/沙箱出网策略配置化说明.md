# 沙箱出网策略配置化说明

## 1. 背景与需求

web 版智能体沙箱的出网白名单原本**硬编码**在 `_default_network_policy()` 中
（`pypi.org`、`*.github.com`、`*.baidu.com`），`.env` 的 `SANDBOX_ALLOWED_DOMAINS`
只作为「额外追加」域名。需求有两条：

1. 把默认白名单收敛到 `.env`，代码内不再内置任何默认域名；
2. 提供三种可配置的出网模式——**仅白名单 / 不受限制 / 完全禁网**，全部通过 `.env` 切换。

## 2. 配置项

| 环境变量 | 取值 | 含义 |
| --- | --- | --- |
| `SANDBOX_NETWORK_MODE` | `whitelist`（默认） | 仅允许访问 `SANDBOX_ALLOWED_DOMAINS` 中的域名 |
| | `allow_all` | 沙箱可不受限制地访问网络 |
| | `deny_all` | 沙箱完全不可访问网络 |
| `SANDBOX_ALLOWED_DOMAINS` | 逗号分隔域名 | 仅 `whitelist` 模式生效；代码内不再内置默认值 |

三种模式在**创建沙箱时**下发的 `NetworkPolicy`：

| 模式 | defaultAction | egress 规则 |
| --- | --- | --- |
| `whitelist` | `deny` | 白名单域名（含调用方附加域名）的 allow 规则 |
| `allow_all` | `allow` | 无（无需规则） |
| `deny_all` | `deny` | 无 |

> `defaultAction` 只能在创建沙箱时设定（侧车只提供 `GET/PATCH/DELETE /policy`，
> 其中 `PATCH` 只改规则、不改 defaultAction）。因此修改 `SANDBOX_NETWORK_MODE` 后，
> 需要重启服务并等旧沙箱被回收/重建才会生效。

## 3. 会话「联网访问」开关与模式的关系

全局模式决定**上限**，会话开关只在 `whitelist` 模式下生效：

| 模式 | 会话开关关闭 | 会话开关开启 |
| --- | --- | --- |
| `whitelist` | 用同域名的 deny 规则覆盖放行，沙箱完全不可出网 | 下发白名单 allow 规则 |
| `allow_all` | 忽略（运行时无法收紧默认动作） | 忽略 |
| `deny_all` | 忽略（已完全禁网） | 忽略（无法放开） |

## 4. 代码改动

### 4.1 `web/backend/src/agent/config/config.py`

- 新增模式常量 `SANDBOX_NETWORK_MODE_WHITELIST` / `_ALLOW_ALL` / `_DENY_ALL` 与 `SANDBOX_NETWORK_MODES`。
- 新增配置项 `SANDBOX_NETWORK_MODE`（默认 `whitelist`）与规范化属性 `sandbox_network_mode`
  （大小写不敏感，非法值回退 `whitelist`）。

### 4.2 `web/backend/src/agent/sandbox/opensandbox_operate.py`

- 删除硬编码的三条 `NetworkRule`；新增 `merge_allowed_domains()`（合并、去重、保序）、
  `allow_network_rules()`、`deny_network_rules()`。
- `_default_network_policy()` 改为按 `SANDBOX_NETWORK_MODE` 构建创建期策略。

### 4.3 `web/backend/src/agent/sandbox/sandbox_policy.py`

- `apply_network_policy()` 按模式生效：`whitelist` 下开启下发 allow、关闭下发 deny；
  `allow_all` / `deny_all` 直接返回，会话开关不参与。
- 关闭分支**不再调用 `delete_egress_rules`**：当前 OpenSandbox 侧车未实现 `DELETE /policy`
  （实测返回 `405 Method Not Allowed`），而 `PATCH /policy` 对相同 target 具备覆盖语义，
  用 deny 规则覆盖同样能达到「关闭」的效果。

### 4.4 配置与文档

- `.env` / `.env.example` 增加 `SANDBOX_NETWORK_MODE` 并说明三种取值。
- 更新 `web/backend/docs/Ke-Hermes-后端详细设计说明书.md` 的环境变量表
  （该目录已被 `.gitignore` 忽略，改动仅保留在本地）。

## 5. 测试

`web/backend/tests/unit_tests/test_request_permission.py` 新增 7 条用例：

- 三种模式各自的创建期策略（`defaultAction` 与规则集合）；
- 非法模式值回退 `whitelist`；
- `whitelist` 下会话开关的 allow / deny 下发，并断言**不会**调用 `delete_egress_rules`；
- `allow_all` / `deny_all` 下会话开关不产生任何改动。

## 6. 行为影响

- 默认 `whitelist` 与改造前一致，但「关闭联网」现在**真的生效**（改造前因 405 失败且被静默吞掉）。
- `whitelist` 模式下 `SANDBOX_ALLOWED_DOMAINS` 留空等价于完全禁网。
- 其余两个模式会让会话开关失效（这是有意为之：模式即管理员设定的硬上限）。
