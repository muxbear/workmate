# 技能仓库真实抓取与「校验失败不入库」修复说明

## 1. 背景

1. web 版「技能 → 创建技能 → 从仓库下载」原来是前端硬编码的 mock 列表（固定 10 条 + 1 秒假延时），导入出来的是只有元数据、没有 `scripts/` 的空壳技能，无法满足「带 JS / Python 脚本的技能」这条需求。
2. 上传技能包时，校验失败的技能仍会被复制到 `workspace/skills_upload/` 并写入 `skills` 表（`valid=false`），随后还会被桌面端同步到本地——这是缺陷 DEF-01。

本次把第 1 点改成真实抓取权威技能仓库榜单，把第 2 点改成「校验失败完全不落盘、不入库、不同步」。

## 2. 抓取源选择

| 来源 id | 名称 | 仓库 | 权威性 | 说明 |
| --- | --- | --- | --- | --- |
| `anthropic-official` | Anthropic 官方技能仓库 | `github.com/anthropics/skills` | official | 第一方维护，`skills/<name>/SKILL.md` 结构 |
| `superpowers` | Superpowers 技能库 | `github.com/obra/superpowers` | community | GitHub 28 万+ stars，MIT，`skills/<name>/SKILL.md` 结构 |

被替换掉的来源：

- **ClawHub**：`https://clawhub.ai/api/skills` 返回 404，没有公开可抓取接口，无法真正抓取。
- **skills.sh**（Vercel 的 The Agent Skills Directory）：有官方 API，但强制要求 Vercel OIDC 鉴权（无 token 返回 401 `authentication_required`），WorkMate 后端不在 Vercel 上运行，无法使用。

抓取方式选择 GitHub REST API + 仓库 tarball 快照，而不是逐文件请求 `raw.githubusercontent.com`：实测 `raw.githubusercontent.com` 在本机网络下不可达，而 `api.github.com` 与 `codeload.github.com` 可稳定访问。

## 3. 后端改动

### 3.1 新增 `web/backend/src/api/skill/repository.py`

- **抓取**：
  - `GET /repos/{repo}` 取 `stargazers_count`（热度）与 `default_branch`；
  - `GET /repos/{repo}/tarball/{branch}` 一次性拉取仓库快照，本地用 `tarfile` 解析出 `skills/<name>/SKILL.md` 及其文件清单；
  - 每个来源只发 2 个请求，避免逐文件请求和二次限流。
- **榜单排序**：`权威级别（官方优先） → 仓库星标数 → 技能名`，响应返回 `rank`、`popularity`、`rank_basis`、`fetched_at`。
- **缓存**：默认 TTL 1800 秒；支持 `refresh=true` 强制刷新；刷新失败沿用最近一次成功快照。
- **配置项**：`SKILL_REPO_GITHUB_TOKEN`（提升 GitHub 配额）、`SKILL_REPO_CACHE_TTL`、`SKILL_REPO_MAX_TARBALL_MB`、`SKILL_REPO_MAX_CACHE_MB`、`SKILL_REPO_TIMEOUT`。
- **导入**：解压选中技能 → 路径穿越校验 → 复用 `validate_skill_directory` 校验 → **仅校验通过才落盘 + 入库**（`source` 记为来源 id）。

### 3.2 接口

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/api/skill/repo/sources` | 列出已注册的权威技能仓库来源 | 登录 |
| GET | `/api/skill/repo/list` | 抓取榜单（`source` 必填，支持 `keyword`/`page`/`page_size`/`refresh`） | `skill:read` |
| POST | `/api/skill/repo/import` | 导入选中技能（`{source, skill_ids}`） | 登录 |

### 3.3 缺陷 DEF-01 修复（`service.py`）

- `process_skills_upload`：`result.valid === false` 时直接 `continue`，不再 `shutil.copytree`、不再 `db.add`；
- 校验通过的技能 `valid` 固定写 `True`，`validation_errors` 置空；
- `list_skills` / `search_skills` 增加 `Skill.valid.is_(True)` 条件，历史遗留的 `valid=false` 记录不再对外暴露，也不会被桌面端同步。

## 4. 前端改动

- `SkillDialog.vue`「从仓库下载」页签：
  - 来源下拉由 `/skill/repo/sources` 填充（原硬编码的 ClawHub / LangChain / CrewAI / AutoGen 已移除）；
  - 「获取」调用 `/skill/repo/list`，真实抓取并展示榜单；
  - 列表展示 `#排名 · 仓库星标数`；
  - 「导入」调用 `/skill/repo/import`，成功后刷新技能列表；
  - 「自定义地址」暂不支持（后端只接受已注册来源，避免任意 URL 抓取带来的 SSRF 风险），点击会提示改选已注册来源。
- `services/skillApi.ts`：新增 `fetchRepoSkillSources` / `fetchRepoSkills` / `importRepoSkills`。
- `types/skill.ts`：新增仓库来源、榜单、导入相关类型；`SOURCE_LABELS` 增加 `anthropic-official` 与 `superpowers`。

## 6. 更新的测试用例

### WEB-05R 校验失败必须完全拒绝（P0，替换原 WEB-05 预期）

步骤：上传 C1–C4 反例包（name 不一致 / 缺 description / 无 frontmatter / 目录名不合规）。

预期（四条同时成立）：

1. `valid_count=0`、`invalid_count=1`，页面标红并给出字段级原因；
2. **不落盘**：`<WORKSPACE>/skills_upload/<name>` 不存在，同名已存在目录内容不被替换；
3. **不入库**：`skills` 表无该记录，`GET /api/skill/list` 不返回；
4. **不同步**：桌面端重新同步后不出现该技能，`stats.added` 不因它增加。

批量包部分失败：通过项正常落盘入库，失败项不落盘不入库，响应分别列出。

### WEB-07 从权威榜单真实抓取并导入（P0）

步骤：

1. 创建技能 →「从仓库下载」，确认来源下拉只包含 `Anthropic 官方技能仓库` 与 `Superpowers 技能库`；
2. 选择来源点「获取」；
3. 核对列表排序、排名与星标数展示；
4. 勾选带 Python 脚本与带 JS 脚本的技能各一个，执行导入；
5. 回到技能列表核对，并检查落盘与入库。

预期：

1. 列表为真实抓取结果（来源标识、排名、星标数、抓取时间齐备），不是固定条目；
2. 排序符合「权威优先 → 星标数 → 技能名」；
3. 导入后是完整技能包：`skills_upload/<name>/SKILL.md` 与 `scripts/*` 等原样落盘，`skills` 表 `valid=true`、`source` 为来源 id；
4. 导入的 Python 技能在桌面端安装后 `runtime.kinds=["python"]`，JS 技能为 `["node"]`；
5. 二次导入同名技能提示跳过且不覆盖。

### WEB-07R 抓取失败不得回退假数据（P0）

步骤：断网或让 GitHub 返回超时/限流后点击「获取」。

预期：给出可读错误（超时/限流/资源不存在），列表为空，页面不出现任何硬编码技能；恢复网络后重试成功。若响应中返回 429，提示配置 `SKILL_REPO_GITHUB_TOKEN`。

### DESK-10 桌面端不得同步无效技能（P0）

步骤：先确认 WEB-05R 的无效包已被拒绝；再对一个已存在历史 `valid=false` 记录的库执行桌面端「重新同步」。

预期：技能页无无效技能卡片，`~/.ke-work/skills/skills.json` 无对应条目，不会为其准备运行时，也不会出现在「新建任务」的技能菜单。

### E2E-04 榜单导入全链路（P0）

步骤：WEB-07 从榜单导入 Python / JS 技能各一 → 桌面端同步 → 安装 → 新建任务添加并提问。

通过标准：全链路真实可用，导入包为完整包（非空壳）；Python 走 Python 运行时、JS 走 Node 运行时；脚本输出与手工执行一致。

## 7. 已知限制

1. 「自定义仓库地址」暂不支持；如需支持，应在后端增加白名单/来源注册机制，而不是允许任意 URL。
2. GitHub 未鉴权限流为 60 次/小时；本次已用 tarball + 缓存把每次刷新压缩到每来源 2 个请求，生产环境建议配置 `SKILL_REPO_GITHUB_TOKEN`。
3. 热度为仓库级星标数，同一仓库内技能共享热度；跨仓库的「排名靠前」通过权威优先 + 星标数体现。
4. 首次获取榜单需下载仓库快照（官方约 3.8MB、Superpowers 约 0.6MB），耗时数秒；命中缓存后瞬时返回。
5. 榜单缓存为进程内缓存，后端重启后首次请求会重新抓取。
