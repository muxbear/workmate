# 技能下载站点参数化与下拉框显示修复说明

## 1. 背景与需求

web 版「技能 → +创建技能 → 从仓库下载」左侧的来源下拉，原本只有一个固定来源：后端内置注册表
（`REPO_SOURCES`：Anthropic 官方技能仓库、Superpowers 技能库）。本次需求：

1. 下拉列表数据改为来自「参数配置」页面中**参数编码为 `skill_download_site`** 的参数；
2. 修复点击下拉后**弹出的下拉项无法正常显示**的问题。

## 2. 问题定位（下拉项无法正常显示）

用真实浏览器（Playwright，1440×900）实测旧实现，量到的数据是：

| 元素 | 盒模型 | 说明 |
| --- | --- | --- |
| `.select-dropdown` | x=422, y=346, w=180, h=290 | 下拉面板 |
| `.download-panel` | x=405, y=269, w=630, **h=88** | `overflow: hidden` 的裁剪容器 |

下拉面板从 y=346 开始、高 290px，而它的祖先 `.download-panel` 底边只到 y=357，即**只有约 11px 可见**，
其余全部被 `overflow: hidden` 裁掉；同时面板宽度被 `.custom-select` 限制在 180px，条目名称与说明也被压变形。

根因：下拉面板用 `position: absolute` 渲染在弹窗内部的裁剪容器里。弹窗未展开结果时
`.download-panel` 高度只有 88px，必然把下拉面板裁掉。

## 3. 前端改动（`web/frontend/src/components/skill/SkillDialog.vue`）

- 下拉面板改为 `<Teleport to="body">` + `position: fixed` 定位：位置由触发按钮的 `getBoundingClientRect()`
  计算，滚动/窗口缩放时跟随更新；`z-index: 10050` 高于弹窗遮罩（9999），最小宽度 280px，最高 320px 可滚动。
  这样面板不再受任何弹窗容器 `overflow: hidden` 影响。
- 点击外部关闭：同时判断触发按钮区域与（已挂到 body 的）下拉面板，点击选项不再被误判为「点击外部」。
- 数据来源：打开弹窗、切换到「从仓库下载」标签页时都会重新拉取来源
  - 先调 `GET /api/params/skill_download_site/children` 读取「参数配置」中 `skill_download_site` 的子参数
    （参数编码 = 来源 id、参数标签 = 站点名称、参数值 = 仓库地址、描述 = 站点说明）；
  - 参数不存在、为空或当前账号无 `admin:params` 权限时，回退 `GET /api/skill/repo/sources`（内置来源），保证老行为可用。
- 选中态与地址回填改为按来源 id 比较，避免两个站点同 URL 时勾选错乱。

## 4. 后端改动（`web/backend/src/api/skill/repository.py`、`skill_api.py`）

- 新增 `load_configured_sources(db)`：读取参数编码为 `skill_download_site` 的参数，支持两种配置形态

  | 形态 | 配置方式 | 转换规则 |
  | --- | --- | --- |
  | 父级分组 + 子参数（推荐） | 参数配置页新建父级参数 `skill_download_site`，再逐个新增子参数 | 子参数编码 = 来源 id；标签 = 站点名称；值 = 仓库地址；描述 = 站点说明 |
  | 单参数 JSON | 参数 `skill_download_site`，值为 JSON 数组或 `{名称: 地址}` 映射，也支持逗号/换行分隔的地址列表 | 条目键 `id/code`、`name/label`、`url/homepage/value`、`description/desc`、`repository/repo`、`skills_path`、`authority` |

- 新增 `effective_sources(db)`：**参数配置优先，未配置时回退内置 `REPO_SOURCES`**；
- 新增 `parse_repository_url`：支持 `https://github.com/owner/repo`、`…/repo.git`、`git@github.com:owner/repo.git`、
  简写 `owner/repo`，以及带目录的 `https://github.com/owner/repo/tree/main/<skills 目录>`；
- `/api/skill/repo/sources`、`/api/skill/repo/list`、`/api/skill/repo/import` 统一改用生效来源；
  `/repo/list` 与 `/repo/import` 增加 `db` 依赖（来源来自参数，需要读库）；
- 榜单缓存 key 改为「来源集合（id/仓库/技能目录）」，参数变更后会自动重新抓取；
- 多来源抓取时单个来源失败只跳过并记录告警，全部失败仍抛出错误（保持「抓取失败不回落假数据」）。

## 6. 兼容性与注意事项

1. 未配置 `skill_download_site` 时，下拉内容与改造前完全一致（内置两个来源）；
2. 站点参数值需要是可解析的仓库地址（`owner/repo` 或 GitHub 仓库 URL），否则点击「获取」会返回
   「技能下载站点「xxx」未配置有效的仓库地址（形如 owner/repo）」的可读提示；
3. 后端在 Windows 下不开启 uvicorn reload，改动后端代码后需要重启 `uv run python run.py` 才会生效；
4. 「自定义地址」入口维持原状（后端只接受已注册来源，避免任意 URL 抓取的 SSRF 风险）。
