# 桌面版专家同步方案（重构）

> 状态：待评审
>
> 适用范围：桌面版（ke-work）专家页同步与本地存储。
>
> 需求一句话：点击“同步专家”→ 调用后端专家接口 → 展示同步进度条 → 将数据写入 `~/.ke-work/experts/experts.json` → 页面从该文件加载并展示 → 进度条关闭。

## 一、现状梳理

### 1.1 后端

- `GET /api/expert-sync/list`（OAuth2 `expert:read` scope）一次返回全部已发布专家的 `{ items, total, synced_at }`，无分页参数。
- 响应外层为统一 `ApiResponse` 信封：`code === 0` 视为成功。
- 对应文件：`web/backend/src/api/experts/sync_api.py`、`web/backend/src/api/experts/service.py`。

### 1.2 桌面端

当前链路：

```text
ExpertPage.vue
  → window.api.expert.sync()（IPC：expert-sync:sync）
    → ExpertSyncService.sync()
      → OAuth2 鉴权（expert:read）
      → GET /api/expert-sync/list
      → mapExpert() 映射为 DesktopExpert[]
      → 仅存入内存 cachedExperts
  → catalog.setExperts() 渲染
```

关键事实：

| 模块 | 文件 | 现状 |
|---|---|---|
| 同步服务 | `desktop/src/main/experts/ExpertSyncService.ts` | 拉取后仅内存缓存，无落盘；重启后缓存丢失 |
| IPC | `desktop/src/main/ipc/expert-sync-handlers.ts` | 已有 `status/authorize/sync/cached/disconnect` 通道 |
| Preload | `desktop/src/preload/index.ts`、`index.d.ts` | 暴露 `window.api.expert.*`，无进度事件 |
| 页面 | `desktop/src/renderer/src/views/ExpertPage.vue` | 有 `syncStatus`，无可见进度条；挂载时读内存缓存并自动同步 |
| 数据目录 | `desktop/src/main/data-dir.ts` | 基础目录 `~/.ke-work`（`KE_WORK_HOME` 可覆盖），子目录仅有 `logs/cache/workspace/binaries` |
| 设置页 | `desktop/src/renderer/src/components/settings/pages/SystemSettingsPage.vue` | “存储”分组展示“~/.ke-work 存储空间”，该目录即 DataDirectory 基础目录 |

### 1.3 可复用模式

桌面端已有“主进程推进度事件 → preload 订阅 → store 更新 → 进度条 UI”的成熟先例：

- `runtime:progress`：主进程 `event.sender.send` → preload `onRuntimeProgress(cb)` 返回取消订阅函数。
- 渲染层 `store/runtime.ts` 订阅并维护 `progressMap`。
- `SecurityPage.vue` 以 `.s-progress-bar / .s-progress-fill` 展示百分比进度条。
- 技能同步已抽成 `store/skillSync.ts` 状态模块，专家页目前为内联逻辑。

## 二、差距分析

1. **无持久化**：同步结果只存在于内存，重启后离线不可用。
2. **无“从文件加载”的数据流**：页面没有以磁盘文件为权威来源的读取路径。
3. **无进度条**：`syncStatus` 只驱动按钮禁用，没有进度反馈。
4. **状态层不一致**：专家同步没有独立渲染层 store，登出时也未清理渲染层专家状态。

## 三、目标数据流

将 `~/.ke-work/experts/experts.json` 作为专家数据的“本地事实源”：

```text
点击“同步专家”
  → 授权检查 / 授权（0–10%）
  → 请求 /api/expert-sync/list（10–70%）
  → 映射为 DesktopExpert 并原子写入 experts.json（70–85%）
  → 主进程从 experts.json 读回并校验（85–95%）
  → catalog.setExperts + nextTick 渲染（95–100%）
  → 进度条关闭

进入“专家”页面
  → loadLocal 读 experts.json 直接展示（离线可用）
  → 已授权时可选静默后台刷新，不打断浏览
```

## 四、本地文件契约

### 4.1 存储位置

```text
<dataBaseDir>/experts/experts.json
```

- `dataBaseDir` 即设置页“~/.ke-work 存储空间”目录，由主进程 `DataDirectory` 统一解析，渲染层不接触路径。
- 将 `'experts'` 加入 `desktop/src/main/data-dir.ts` 的 `SUB_DIRS`，启动时 `ensureAll()` 创建；存量环境首次同步时由 store 内 `mkdirSync(recursive)` 兜底。

### 4.2 文件格式

```jsonc
// ~/.ke-work/experts/experts.json
{
  "version": 1,
  "syncedAt": 1757068800000,
  "syncedBy": { "webUserId": "u_xxx", "nickname": "demo" },
  "experts": [
    // DesktopExpert[] 原样序列化，即 ExpertPage 卡片直接消费的结构
  ]
}
```

说明：

- `version` 用于后续结构迁移。
- `syncedBy` 记录数据来源账号，便于追溯；本期为机器级单文件。
- 文件缺失 / JSON 损坏时不阻塞页面：返回空并记录 warn，不自动删除旧文件；下次成功同步再覆盖。

### 4.3 写入策略

原子写，避免进程中断产生半截文件：

```text
先写 experts.json.<pid>.tmp
→ rename 为 experts.json
```

写失败（磁盘满 / 权限）时不修改旧文件，也不清空内存展示，仅向渲染层报错。

## 五、主进程设计

### 5.1 新增 ExpertJsonStore

文件：`desktop/src/main/experts/ExpertJsonStore.ts`

职责单一、可脱离网络测试：

| 方法 | 职责 |
|---|---|
| `read(): { experts: DesktopExpert[]; syncedAt: number } \| null` | 读文件、校验 `version` 与结构；缺失/损坏返回 `null` 并 warn |
| `write(payload): Promise<void>` | 原子写（tmp + rename） |

### 5.2 重构 ExpertSyncService

文件：`desktop/src/main/experts/ExpertSyncService.ts`

变更点：

- 构造函数注入 `dataDir`（或 `expertsDir`），内部持有 `ExpertJsonStore`。
- `sync(localUserId, onProgress?)`：拉取 → 映射 → 写盘 → **读回校验**，返回 `{ syncedAt, experts }`，其中 `experts` 为读回结果，保证与磁盘一致。
- 新增 `loadLocal()`：读 `experts.json` 返回数据，供页面挂载与同步完成后加载。
- `disconnect()`：撤销 token、清内存缓存；**不删除 experts.json**，保证未授权 / 离线时仍可浏览上次同步数据。
- 内存缓存仅作为读盘后的进程内副本，不再作为权威数据源。

进度通过回调解耦，service 不依赖 Electron：

```ts
type ExpertSyncPhase = 'authorize' | 'fetch' | 'save' | 'load' | 'done' | 'error'

interface ExpertSyncProgress {
  phase: ExpertSyncPhase
  percent: number      // 0–100，单调递增
  message: string      // 如“正在拉取专家数据…”
  received?: number
  total?: number
}
```

## 六、IPC 与 Preload 契约

### 6.1 通道调整

文件：`desktop/src/main/ipc/expert-sync-handlers.ts`

| 通道 | 现状 | 重构后 |
|---|---|---|
| `expert-sync:status` | 返回授权状态 | 不变 |
| `expert-sync:authorize` | 浏览器授权 | 不变 |
| `expert-sync:sync` | 返回 `{ experts, syncedAt }`，纯内存 | 拉取 + 落盘 + 读回，期间推送进度 |
| `expert-sync:cached` | 返回内存缓存 | 改为 `expert-sync:load-local`，读磁盘文件 |
| `expert-sync:progress` | 无 | 新增主进程 → 渲染层事件 |
| `expert-sync:disconnect` | 清内存 | 撤销授权、清内存；不删文件 |

`sync` 处理器把进度回调接到当前调用方的 sender：

```ts
const onProgress = (p: ExpertSyncProgress): void => {
  event.sender.send('expert-sync:progress', p)
}
// 进入 sync 前绑定，finally 中解绑，避免泄漏到其他窗口
```

### 6.2 Preload

在 `window.api.expert` 上新增（对齐 `onRuntimeProgress` 模式）：

```ts
onSyncProgress(callback: (data: ExpertSyncProgress) => void): () => void
// 内部 ipcRenderer.on('expert-sync:progress', handler)，返回取消订阅函数
```

同时更新 `desktop/src/preload/index.d.ts` 中 `ExpertSyncAPI` 与新增的 `ExpertSyncProgress` 类型。

## 七、渲染层设计

### 7.1 新增 expertSync store

文件：`desktop/src/renderer/src/store/expertSync.ts`

镜像 `store/skillSync.ts` 的结构：

- state：`status / webUser / lastSyncedAt / percent / progressMessage / syncing / error`。
- `loadLocal()`：调 `window.api.expert.loadLocal()` → `catalog.setExperts()`。
- `sync()`：订阅 `onSyncProgress` 更新进度；成功后 `loadLocal()` 渲染，`await nextTick()` 后置 100% 并淡出；异常时置 `error`，保留旧列表。
- 同步中守卫：`syncing === true` 时重复点击直接忽略。
- `resetLocal()`：清空渲染层状态与专家列表（登出时调用）。

### 7.2 ExpertPage 流程

文件：`desktop/src/renderer/src/views/ExpertPage.vue`

1. 挂载：`loadLocal()` 先展示本地专家；已授权时是否自动后台刷新见“风险与待确认事项”。
2. 点击“同步专家”：未授权先 `authorize()`（文案提示“请在浏览器中完成授权”）→ `sync()` → 渲染。
3. 去掉旧 `syncStatus` / 内联 `loadExperts` / `handleSync`，改用 store，行为与 SkillPage 对齐。

### 7.3 进度条 UI

- 位置：top-bar 下方或按钮旁。
- 样式：沿用 `SecurityPage.vue` 的 `.s-progress-bar / .s-progress-fill` 与 `--kw-color-brand` 主题变量。
- 内容：细进度条 + 百分比 + 阶段文案（如“正在保存专家数据… 80%”）。
- 关闭条件：`catalog.setExperts` 完成并 `nextTick` 渲染后，进度置 100%，短暂淡出隐藏。

阶段权重建议（单次全量请求无服务端进度，采用“阶段加权 + 下载字节”映射）：

| 阶段 | 进度区间 | 触发点 |
|---|---|---|
| authorize | 0–10 | 状态检查 / 浏览器授权 |
| fetch | 10–70 | HTTP 拉取；axios `onDownloadProgress`，有 Content-Length 时按字节映射，无则按 25/45/65 分档推进 |
| save | 70–85 | experts.json 写入完成 |
| load | 85–95 | 读回文件并校验 |
| render | 95–100 | `catalog.setExperts` + `nextTick` 后 |
| done | 100 | 进度条关闭 |

## 八、后端：本期保持不变

- 现有 `/api/expert-sync/list` 单请求全量返回已满足需求，进度条由客户端阶段化呈现，不需要引入 SSE / WebSocket。
- 若未来专家量级明显增大，可给该接口加分页参数，客户端按 `total/page_size` 循环拉取获得真实进度，属可选演进，本期不做。

## 十一、风险与待确认事项

1. **账号维度**：需求指定固定 `experts/experts.json`，本期实现为机器级单文件，文件内以 `syncedBy` 记录来源。若后续支持多本地账号各自维护专家数据，可改为 `experts/<webUserId>/experts.json` 分桶。
2. **disconnect 语义**：建议断连 / 登出只清授权与渲染层状态、保留文件，保证离线浏览；如需“断开即清除本地专家”，则 `disconnect` 再删除文件，属产品决策。
3. **进入页面是否自动刷新**：现代码在已授权时挂载即自动同步；按“点击同步专家”的交互描述，建议挂载只读本地、点击才同步。若要保鲜，可保留静默后台刷新但不显示进度条。
4. **进度真实性**：单请求接口下无法提供服务端分页级进度，采用“阶段加权 + 下载字节”方案保证连续感知；不要为实现真实进度而本期引入分页或流式接口。
