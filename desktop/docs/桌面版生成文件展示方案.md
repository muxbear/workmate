# 桌面版“生成文档自动展开右侧栏 + 流式文档预览 + 历史回显一致”实现方案

> 状态：已按本方案完成第一轮实现（2026-09-05）
> 适用仓库：`desktop/`（Electron 39 + Vue 3 + TypeScript + DeepAgents）

## 1. 需求背景与目标

用户在“新建任务”对话态提交问题后，大模型边回答边生成文档。期望：

1. 大模型回答过程中若回复涉及生成文档（如 markdown、docx、html、txt、json 等），主动展开对话态右侧栏，并按文档类型选择系统支持的组件展示该文档（行为等同“工作空间文件模式下打开该文件”）。
2. 右侧文档内容按流式输出逐 token 显示。
3. 右侧打开文档后，左右宽度占比为 6:4。
4. 历史对话展示区域中展示的文件名带超链接，点击后在右侧打开该文件（若右侧尚未打开）。
5. 实时对话消息与“从主页面左侧会话列表重新打开并回显历史对话”的展示样式、排版严格一致；回显数据来自 LangGraph checkpoints 表，需核对消息类型与存储格式，并检查当前回显处理逻辑。

## 2. 现状核对结论

### 2.1 LangChain 官方文档核实

- 官方文档：[Messages（LangChain.js）](https://docs.langchain.com/oss/javascript/langchain/messages) 确认核心消息类型为 4 类：
  - `SystemMessage`：系统指令；
  - `HumanMessage`：用户输入；
  - `AIMessage`：模型输出（含文本、tool_calls、元数据）；
  - `ToolMessage`：工具执行结果，必须携带 `tool_call_id`。
  - 流式过程会出现 `AIMessageChunk` 等派生类型，最终合并为完整消息。
- 官方文档：[Checkpointers（LangGraph）](https://docs.langchain.com/oss/javascript/langgraph/checkpointers) 确认：checkpoint 是线程（thread）在图各 super-step 的状态快照，消息保存在状态通道（如 `channel_values.messages`）中；JS 侧 Sqlite/Postgres saver 把序列化后的完整快照存为 BLOB/JSON，并不把消息“拆列”存储。
- 结论：用户对“应有 4 类消息”的理解正确；但实际会话不一定都出现 `SystemMessage`（系统提示常由运行时注入而不落库），且 LangChain 序列化采用 `{lc, type: 'constructor', id: ['langchain_core', 'messages', 'HumanMessage'], kwargs: {...}}` 扩展 JSON 形态。

### 2.2 本地 checkpoint 数据实测（ke-work.db 只读抽样）

- checkpoints/writes 两表均非空；checkpoint 列为序列化 JSON，包含 `channel_values.messages` 等通道。
- 抽样会话消息序列：HumanMessage、AIMessage（含 reasoning / text / tool_call 块）、ToolMessage（name、tool_call_id 独立），未出现 SystemMessage。
- 写文件示例：AI 工具调用 `write_file`，参数为 `file_path: “/秋日私语.md”` 与完整 `content`；ToolMessage 内容如 `Successfully wrote to '…'`。文档还可能由子智能体（task 工具）内部生成，父级只留下 TaskMessage 文本（含“保存信息 / 文章文件 / 已写入”等路径表述）。
- LangChain v3 流接口（`streamEvents(..., {version:'v3'})`）在 `events.messages` 之外还暴露：
  - `run.toolCalls`：`{ name, callId, input, output, status }`；
  - `run.subagents`：每个子智能体流再暴露自身的 `toolCalls`。
  这是“生成文档”的权威信号来源。

### 2.3 当前代码问题清单

- `service.ts` 只遍历 `events.messages` 的 `reasoning` / `text`，未转发工具调用或文件写入，也没有“文档产物”载体。
- `ChatSidePanel.vue` 的 `open/expandPanel/openFile` 均为内部状态，无对外可调用 API；右栏宽度为像素制并可拖拽，未实现 6:4 比例态。
- 消息区只展示 `msg.content/reasoning`，文件名是普通文本，无可点击打开动作。
- 历史回显与实时展示不一致：
  - `getMessages` 保留 tool/system 消息，而模板把“非 assistant”一律渲染成用户气泡 → 工具消息回显为“用户样式的工具条”；
  - 同一轮回复在 checkpoint 中可能是多条内部 AIMessage（reasoning/tool_call 阶段 + 最终文本阶段），历史回显会出现多条 AI 气泡，而实时只显示一条；
  - 实时 assistant 消息带 `createdAt/durationMs/model`，历史回显无这些字段；
  - `toLangChainMessages` 用 ToolMessage 自身 id 作为 `tool_call_id` 重建历史，属于潜在正确性缺陷（靠 reducer 按 id 去重才未暴露）。

## 3. 总体设计

采用“工具事件驱动 + 正文链接兜底”：

- 主进程把 `write_file/edit_file/task/execute` 中产生的文档路径与内容作为权威信号，推送流式产物事件并持久化“产物清单 + 消息元信息”；
- 渲染层监听产物事件，自动展开右侧栏并按扩展名选择组件（复用现有工作空间文件打开链路）；
- 历史回显基于 checkpoint 做“按轮折叠归一”，与实时消息共用同一渲染模板与同一数据形状，确保样式排版一致。

## 4. 关键改动

### 4.1 主进程：文档产物检测、推送与持久化

- 在 `desktop/src/main/agent/service.ts` 中并发遍历：
  - `run.toolCalls`（父级工具调用）；
  - `run.subagents[].toolCalls`（递归嵌套子智能体工具调用）。
- 文档识别规则：
  - `write_file` / `edit_file`：取 input 的 `file_path`（去前导 `/`、`\` 归一为 `/`、containment 越界校验）与 `content`；
  - `task` / `execute`：从返回文本中正则提取工作区内且扩展名命中白名单的路径（覆盖“保存信息 / 文章文件 / 已写入”等表述），仅接受落在会话绑定或默认 workspace 目录内的路径；
  - 白名单 `DOC_EXTENSIONS`：md、html、htm、txt、json、csv、yaml、yml、xml、doc、docx、pdf；代码/图片等其他扩展名不触发自动展开。
- 推送事件（沿用 `win.webContents.send`）：
  - `agent:artifact-start`：`{ artifactId, name, relPath, workspaceId, ext, preview }`；
  - `agent:artifact-chunk`：`{ artifactId, text }`；
  - `agent:artifact-end`：`{ artifactId, ok }`；
  - `agent:artifact-error`：`{ artifactId, error }`。
- 流式策略：
  - 文本型（md/html/txt/json 等）：工具参数已含完整 content，主进程按小片（约 8~32 字符/次）推送，渲染层按 rAF 合并更新，实现 UI 逐 token 展开；
  - 二进制型（doc/docx/pdf）：start 后展示“生成中…”，工具执行完成后 end，渲染层再读字节交给 WordEditor/PdfPreview。
- 持久化（复用现有本地 SQLite + 迁移机制）：
  - `conversation_turn_meta`：`(user_id, conversation_id, turn_index)` → `model / created_at_ms / duration_ms`；
  - `conversation_doc_artifacts`：`(user_id, conversation_id, turn_index, rel_path)` → `name / ext / workspace_id`；
  - 迁移版本追加 v9（当前最大 v8）；
  - `deleteConversation`、删除工作空间级联删除会话时同步清理；
  - `agent:send` 的 regenerate 分支在截断前删除 `turn_index >= 本轮` 的元信息与产物行。
- 渲染层发送消息时携带展示性元信息（`opts.turnIndex/model/createdAt`），模型选择仍只信任 `customModelId` 校验；流结束后由新 IPC `conversation:save-turn-meta` 补写 durationMs。

### 4.2 渲染层：右侧栏流式文档与公开 API

- `ChatSidePanel.vue` 增加 `defineExpose`：
  - `openArtifact(meta)`：展开面板 → 切到“工作空间文件”视图 → 按扩展名创建文档标签并接收后续 chunk；
  - `openDocFileByRelPath(relPath)`：历史/链接点击复用现有 `openFile` 逻辑，标签已存在则聚焦；
  - `collapse()`。
- FileTab 增加流式态：
  - 文本型：现有 `FilePreview` 展示（md 用 marked 随内容增量渲染，其余 `<pre>`）；
  - html：生成期间先按源码流式预览，`artifact-end` 后切换到现有 BrowserPanel 渲染，与“工作空间模式下打开 html”一致；
  - doc/docx/pdf：生成期间“生成中…”，end 后读取字节交给 `WordEditor` / `PdfPreview`。
- 流事件监听收敛到 `agent` store 的 `runStream`：
  - start：把 `{name, relPath, ext, ...}` 追加到当前 assistant 消息 `files` 数组并更新“活动文档”状态；
  - chunk：推进活动文档文本；
  - end / error：收尾；
  - 切换会话 / 重新生成时清理。
- 6:4 布局：
  - `NewTaskPage.vue` 为 `.chat-area` 增加 `doc-ratio` 态：对话区 `flex: 0 1 60%`、右栏 40%；
  - `ChatSidePanel` 增加 `ratioMode` prop，进入比例态时以 40% 覆盖像素宽度；
  - 仅“文档自动展开 / 点击文档打开”时进入；用户拖动分割线、收起或全屏时退出比例态并恢复可拖动像素宽度。
- 消息区文件链接：
  - AI 回复下方渲染统一“生成文档”文件链接条（图标 + 文件名），live 与历史回显共用同一模板；
  - `MessageContent.vue` 的 marked link renderer 增加拦截：href 为工作区相对路径且扩展名命中白名单时输出 `data-open-file` 链接，点击后交由 NewTaskPage → `openDocFileByRelPath`；
  - http(s)、图片、其他链接行为不变。

### 4.3 历史回显一致性（checkpoint 读取归一）

- 拆分两类读取：
  - `ConversationStore.getRawMessages()`：供 `agent:send` 构造模型输入，保留 tool/system 消息与 `tool_call_id`/`name` 原值；修正 `toLangChainMessages` 误用 ToolMessage 自身 id 作为 `tool_call_id` 的问题；
  - `ConversationStore.getMessages()`：供 `conversation:get` 回显，按“user 消息为界”折叠。
- 折叠规则：
  - 一条用户消息对应一条 AI 消息；
  - AI content = 本轮内所有 AIMessage 的 text 块按消息顺序拼接（与实时逐 token 追加顺序一致）；
  - reasoning = 各 AIMessage reasoning 块拼接；
  - tool/system 消息一律不渲染；
  - 每条折叠后的 AI 消息按 `turn_index` 从辅助表补齐 `meta` 与 `files`。
- 用户消息沿用现有附件折叠（`【文件：x】` → 📎）。
- 渲染统一出口：实时与回显使用同一 `Message`/`ConversationMessage` 数据形状（可选 `files`、`meta`）与同一模板，不再出现“工具消息渲染成用户气泡”或“一轮生成多条 AI 气泡”。

## 5. 对外接口与数据变更

- preload 新增事件监听：`onAgentArtifactStart/Chunk/End/Error`；

## 7. 默认与假设

- “逐 token”以工具参数中的完整文本切片推送呈现（LangChain v3 高层流不暴露 write_file 参数的逐字增量）；二进制 docx/doc/pdf 在完成后打开。
- 自动展开仅对 `DOC_EXTENSIONS` 白名单生效；触发源为工具写文件事件，正文 Markdown 文件链接作为次要入口，纯文本裸路径不做强行识别。
- 文档所属工作区一律取会话绑定 workspace（未绑定为当前/默认 workspace）；主进程只放行 workspace 目录内路径。
- 元信息/产物辅助表沿用本地 SQLite（与 conversation_titles 同库），云模式 checkpoint 仍在远端，展示元信息本地兜底。
